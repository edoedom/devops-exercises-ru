<a id="how-to-contribute"></a>
## Как внести вклад в проект

Предлагайте изменения через pull requests.

Используйте следующий формат:

```md
<details>
<summary>[Вопрос]</summary><br><b>

[Ответ]
</b></details>
```

* Если вы добавили несколько вопросов и хотите узнать их общее количество, запустите скрипт `count_questions.sh` из каталога `scripts`.

<a id="what-to-avoid"></a>
## Чего следует избегать

* Не добавляйте вопросы об установке программ: автор считает такой тип вопросов наименее полезным.
* Не копируйте вопросы и ответы из других источников. Их авторы, вероятно, вложили немало труда в подготовку материалов.
* Добавляя изображения, убедитесь, что их можно свободно использовать.

<a id="before-submitting-the-pull-request"></a>
## Перед отправкой pull request

Проверьте изменения локально с помощью скрипта `run_ci.sh` из каталога `scripts`.

Для локальной проверки из корня репозитория нужны Python 3.10+ и зависимости:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
bash scripts/run_ci.sh
```

После добавления вопросов выполните `python scripts/update_question_number.py`. Счётчик включает блоки вопросов и уникальные ссылки на задания в главном README и README разделов, без повторов в материалах сертификаций. CI проверяет его через `--check`, запускает регрессионные тесты, оба Flask-приложения, синтаксис Python/Bash/YAML/HCL и структуру Markdown. Синтаксический разбор IaC не заменяет `terraform validate`, `plan` и проверку в целевой среде. В GitHub Actions проверки выполняются на Python 3.12 и 3.13.

Проверка ссылок работает офлайн: учитываются Markdown reference links, HTML href/src, якоря заголовков и явные id/name. Примеры в code fences не обходятся. Старые README на других языках не входят в проверку навигации русской версии. Для вопросов используйте один summary внутри details и непустой ответ; фрагмент-шаблон выше можно копировать целиком.

Зависимости CI зафиксированы в requirements-dev.lock; обновляйте прямые ограничения и этот файл совместно, затем проверяйте установку в чистом venv. Actions закреплены по полным commit SHA. Изменения зависимостей, workflow, IaC и опубликованных учебных контрактов проходят тот же review, что и программный код.
