<details>
<summary>Что означает соответствие базы данных требованиям ACID?</summary><br>

ACID означает Atomicity, Consistency, Isolation, Durability — атомарность, согласованность, изолированность и долговечность. Необходимо выполнение всех четырёх требований.

**Атомарность.** Изменение базы данных должно либо выполниться целиком, либо не выполниться вовсе.

Например, обновление таблицы должно завершиться полностью. Если выполнена лишь его часть, операция считается неуспешной: изменения откатываются к состоянию до обновления. Каждая транзакция представляет собой самостоятельную неделимую единицу: сбой одной её части приводит к отмене всей транзакции.

**Согласованность.** Каждое изменение должно переводить базу данных из одного допустимого состояния в другое.

Изменения не должны нарушать целостность данных. Для этого в БД заранее определяются проверки и ограничения. Например, если значение несовместимо с типом столбца и не может быть приведено к нему допустимым способом, база данных должна отклонить изменение.

**Изолированность.** Одновременно выполняемые транзакции не должны неконтролируемо влиять друг на друга. В строгом варианте результат соответствует их последовательному выполнению.

Предположим, 20 пользователей одновременно изменяют данные. К моменту вашего запроса 15 изменений завершились, а пять ещё выполняются. В описанном примере вы видите завершённые изменения и не видите промежуточное состояние остальных. Конкретная видимость данных зависит от уровня изоляции и момента создания снимка.

**Долговечность.** Зафиксированные изменения должны сохраняться даже при отключении питания, сбое системы и других отказах. Поэтому завершённые транзакции должны быть записаны в энергонезависимое хранилище.

> Примечание к переводу: исходник связывает ACID с SQL и противопоставляет ему NoSQL. Точнее говорить о гарантиях конкретной СУБД и её настройках: сам язык SQL не обеспечивает ACID, а некоторые NoSQL-системы поддерживают ACID-транзакции.
</details>

</b></details>

<summary>Какие типы данных есть в реляционных базах данных?</summary><br><b>
</b></details>

<details>
<summary>Объясните нормализацию.</summary><br><b>

Многократно используемые данные следует хранить в одном месте, а в остальных ссылаться на них с помощью внешнего ключа.<br>
Это упрощает сопровождение: значение достаточно изменить один раз, чтобы изменение учитывалось везде, где оно используется.
</b></details>

<details>
<summary>Объясните, что такое первичный и внешний ключи.</summary><br><b>

Первичный ключ: уникальный идентификатор строки таблицы.<br>
Внешний ключ: ссылка на ключ другой таблицы. Он позволяет связывать таблицы и получать нужные сведения без дублирования данных.
</b></details>

<details>
<summary>С какими видами таблиц данных вы работали?</summary><br><b>

* Основная таблица: содержит главные данные предметной области.
* Таблица подробностей: содержит внешний ключ и связана с основной таблицей отношением «один ко многим».
* Справочник: отдельная таблица для каждого справочника либо общая таблица справочных значений; используется связь «один ко многим».
* Связующая таблица для нескольких ссылок.
</b></details>

<details>
<summary>Что такое ORM? Какие преимущества она даёт при работе с реляционными базами данных?</summary><br><b>

[Википедия](https://en.wikipedia.org/wiki/Object%E2%80%93relational_mapping): ORM — техника программирования, позволяющая преобразовывать данные между несовместимыми системами типов с использованием объектно-ориентированных языков.

Для реляционных баз данных это даёт:

* Представление структуры БД в коде.
* Абстракцию над базой данных.
* Сокрытие сложности SQL.
* Возможность проводить ревью кода.
* Работу с данными как с обычными объектами языка.
</b></details>
