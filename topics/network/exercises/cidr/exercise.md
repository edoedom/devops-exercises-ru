# IPv4: подсеть и выбор маршрута

Нужен Python 3.10+. Все адреса используются только как числа; программа не отправляет пакеты и не выполняет DNS-запросы.

## Задание

1. Для `198.51.100.0/24` найдите маску, число адресов и обычный диапазон узлов.
2. Сравните `/31` для point-to-point и `/32` для единственного адреса. Не применяйте к ним правило «минус два».
3. Объясните, почему `198.51.100.86/24` — запись интерфейса, а не канонический адрес сети. В данной программе strict=True отклоняет такой ввод.
4. Для адреса `198.51.100.200` выберите маршрут среди `0.0.0.0/0`, `198.51.100.0/24` и `198.51.100.128/25`.
5. Проверьте адрес вне таблицы маршрутизации без default route.

## Запуск и разбор

Из этого каталога:

```bash
python cidr.py 198.51.100.0/24
python cidr.py 198.51.100.0/31
python cidr.py 198.51.100.42/32
```

Для `/24` маска 255.255.255.0, 256 адресов, обычных host-адресов 254: .1–.254. Для `/31` в point-to-point используются оба адреса; для `/32` — единственный. Поле last_address является концом диапазона, но для `/31` и `/32` не означает обычный broadcast.

Из трёх маршрутов выбирается `/25`: он наиболее специфичен. Метрика маршрута и политика нужны при дальнейшем выборе между конкурирующими маршрутами; эта лаборатория моделирует только longest-prefix match по переданным CIDR, а не полную FIB реального маршрутизатора.

Вариант решения — [cidr.py](cidr.py). Регрессии запускаются общим `bash scripts/run_ci.sh` из корня после установки зависимостей. Для IPv6 нужны отдельные правила: маски/размер адреса другие, широковещательного адреса нет. Этот IPv4-пример IPv6-ввод отклоняет.

Источники: [RFC 3021 о /31](https://www.rfc-editor.org/rfc/rfc3021.html), [Python ipaddress](https://docs.python.org/3/library/ipaddress.html).

Число host_count — результат обычных правил адресации подсети, а не обещание выдать столько публичных или облачных адресов. Отдельные специальные диапазоны и дополнительные резервы облачного провайдера учитываются отдельно.
