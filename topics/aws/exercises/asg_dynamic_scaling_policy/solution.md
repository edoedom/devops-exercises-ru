## AWS Auto Scaling Groups: политика динамического масштабирования

<a id="requirements"></a>
### Требования

1. Существующая группа Auto Scaling с максимальным количеством экземпляров не менее трёх.
2. Один работающий экземпляр EC2 с не более чем четырьмя CPU.

<a id="objectives"></a>
### Задание

1. Создайте политику динамического масштабирования:
   1. Отслеживаемый показатель: средняя загрузка CPU.
   2. Целевое значение: 70%.
2. Увеличьте загрузку CPU как минимум до 70%.
   1. Изменилось ли количество экземпляров?
3. Снизьте загрузку CPU ниже 70%.
   1. Изменилось ли количество экземпляров?

<a id="solution"></a>
### Решение

<a id="console"></a>
#### Консоль

1. Откройте **EC2 → Auto Scaling Groups** и вкладку автоматического масштабирования, указанную в исходнике как **Automating scaling**.
2. В поле **Policy Type** выберите **Target tracking scaling**.
3. Укажите метрику средней загрузки CPU.
4. Задайте целевое значение 70% и нажмите **Create**.

Увеличение нагрузки:

1. В Amazon Linux 2 можно использовать следующие команды:

```
sudo amazon-linux-extras install epel -y
sudo yum install stress -y
stress -c 4  # assuming you have 4 CPUs
```

2. В описанном примере добавляется ещё один экземпляр EC2.

Снижение нагрузки:

1. Остановите команду stress.
2. В описанном примере один из экземпляров EC2 завершается.
