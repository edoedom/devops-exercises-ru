# Рассчитать SLO и проверить решение

Нужен Python 3.10+, внешние сервисы и credentials не требуются. Интервалы в requests.json не пересекаются и относятся к одному сервису и одному определению «хорошего» запроса. Числа — дельты событий за интервалы, а не сырые значения сбрасывающихся счётчиков.

## Задание

Для SLO 99,9%:

1. Рассчитайте общий SLI по событиям, допустимое число ошибок и остаток бюджета.
2. Покажите, почему усреднение процентных SLI интервалов даёт неверный результат.
3. Обработайте отсутствие событий отдельно от успеха.
4. Отклоняйте отрицательные счётчики, good > total, дробные счётчики, NaN и неверный SLO.
5. Напишите тесты для точного выполнения SLO и перерасхода бюджета.

Из этого каталога запустите рабочий пример:

```bash
python budget.py --input requests.json --slo 0.999
```

Для всех проверок из корня репозитория: `bash scripts/run_ci.sh` после установки requirements-dev.txt.

## Разбор

Всего 10 000 событий, хороших 9982, плохих 18: SLI = 99,82%. Допустимы 10 плохих событий; остаток = −8, израсходовано 180% бюджета. Значение не обрезается до нуля: иначе будет скрыт размер превышения. Burn rate для этого окна = 1,8.

Среднее двух SLI (99,9% и 99,1%) равно 99,5% и неверно описывает общий поток. Нужно делить сумму хороших событий на сумму допустимых.

Здесь окно расчёта совпадает с окном бюджета, поэтому budget_consumed и burn_rate численно совпадают. При расчёте burn rate на коротком окне и бюджета на длинном они не взаимозаменяемы. Событийное SLO нельзя автоматически переводить в минуты простоя: интенсивность запросов меняется. No Data не сообщает, отсутствовал ли трафик или сломался сбор — для этого нужны дополнительные сигналы.

Не округляйте допустимое число ошибок вверх, чтобы «вписать» лишнее событие в SLO. Пример использует Decimal, чтобы десятичный порог не терял точность из-за binary float.

## Самопроверка

<details>
<summary>При 1000 запросах и SLO 99,9% одна ошибка нарушает цель?</summary>

Нет. Допустима ровно одна ошибка. Две уже нарушают цель.
</details>

<details>
<summary>Можно ли при total = 0 возвращать SLI = 1?</summary>

Нет. Возвращается no_data и отсутствующие производные показатели. Отдельно проверяются трафик, сбор телеметрии и synthetic checks.
</details>
