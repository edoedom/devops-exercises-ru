<a id="shell-scripting---self-assessment"></a>
## Сценарии командной оболочки — самопроверка

<details>
<summary>Что означает строка <code>#!/bin/bash</code> в сценарии оболочки?</summary><br><b>

`#!/bin/bash` — строка shebang, задающая интерпретатор сценария.

/bin/bash — распространённая оболочка, часто используемая по умолчанию при входе пользователя в Linux. Название Bash расшифровывается как Bourne-again shell. Она широко используется благодаря своим возможностям, зрелости и удобному синтаксису и может выполнять множество сценариев оболочки.
</b></details>

<details>
<summary>Верно ли, что при ошибке одной команды сценарий оболочки по умолчанию завершится?</summary><br><b>

Это зависит от языка и настроек. Для обычного сценария Bash утверждение неверно: после неудачного выполнения команды он обычно продолжает выполнять следующие команды.

Часто требуется обратное поведение. Настройка `set -e` позволяет завершать сценарий при ошибке команды, но у неё есть исключения, связанные с контекстом выполнения.

> Примечание к переводу: в оригинале ответ ошибочно помечен как «верно», хотя дальнейшее объяснение описывает продолжение выполнения. Противоречие исправлено.
</b></details>

<details>
<summary>Что вы обычно включаете в каждый свой сценарий?</summary><br><b>

Например:

* Комментарии о назначении и способе запуска.
* Для сценариев оболочки — `set -e`, если требуется остановка при ошибке команды.

Ваш ответ может быть другим: он зависит от опыта и предпочтений.
</b></details>

<details>
<summary>Зачем писать сценарии оболочки, если существуют Ansible, Puppet, Chef и другие инструменты?</summary><br><b>

* Скорость разработки и выполнения простых задач.
* Гибкость.
* Отсутствие нужного модуля. Это не самый сильный довод: большинство систем управления конфигурацией позволяют запускать команды через модуль shell.
* Сценарии передаются клиентам, у которых нет доступа к публичной сети и не обязательно установлен Ansible.
</b></details>

<a id="shell-scripting---variables"></a>
#### Сценарии оболочки — переменные

<details>
<summary>Как определить переменную со значением "Hello World"?</summary><br><b>

`HW="Hello World"`

В оригинале пропущена закрывающая кавычка; здесь она восстановлена.
</b></details>

<details>
<summary>Как записать текущую дату в переменную?</summary><br><b>

`DATE=$(date)`
</b></details>

<details>
<summary>Как вывести первый аргумент сценария?</summary><br><b>

`printf '%s\n' "${1-}"` — выводит аргумент без word splitting и globbing; если аргумент отсутствует, выводит пустую строку. `echo $1` теряет границы слов и может развернуть `*`.
</b></details>

<details>
<summary>Напишите сценарий, который выводит "yay", если аргумент не передан, и значение аргумента, если он передан.</summary><br><b>

```bash
printf '%s\n' "${1-yay}"
```

Без двоеточия подстановка использует запасное значение только для отсутствующего параметра. `${1:-yay}` использует его также для переданной пустой строки.
</b></details>

<details>
<summary>Что выведет следующий сценарий?

```
#!/usr/bin/env bash
NINJA_TURTLE=Donatello
function the_best_ninja_turtle {
        local NINJA_TURTLE=Michelangelo
        echo $NINJA_TURTLE
}
NINJA_TURTLE=Raphael
the_best_ninja_turtle
```
</summary><br><b>
Michelangelo
</b></details>

<details>
<summary>Объясните результат каждой команды:

* <code>echo $0</code>
* <code>echo $?</code>
* <code>echo $$</code>
* <code>echo $#</code></summary><br><b>

В Bash `$0` — имя оболочки или сценария, `$?` — статус последней команды/конвейера, `$$` — PID исходной оболочки, `$#` — число позиционных аргументов. В subshell `$$` не обязательно PID текущего процесса; для него у Bash есть BASHPID. Статус нужно сохранить сразу, пока следующая команда его не изменила.
</b></details>

<details>
<summary>Что такое <code>$@</code>?</summary><br><b>

Все позиционные аргументы. Используйте `"$@"`, чтобы каждый сохранился отдельным аргументом, включая пустые строки и пробелы. `"$*"` объединяет аргументы в одну строку с разделителем из IFS; это другая операция.
</b></details>

<details>
<summary>Чем отличаются <code>$@</code> и <code>$*</code>?</summary><br><b>

В двойных кавычках `"$@"` разворачивается в отдельные аргументы сценария, сохраняя их границы, а `"$*"` — в одну строку с аргументами, разделёнными первым символом IFS.
</b></details>

<details>
<summary>Как получить пользовательский ввод в сценарии оболочки?</summary><br><b>

`IFS= read -r x` читает строку stdin в x, сохраняет пробелы и не интерпретирует обратные косые черты. Статус read нужно учитывать: EOF может сопровождаться последней строкой без завершающего перевода строки. Для такого файла: `while IFS= read -r x || [[ -n $x ]]; do printf '%s\n' "$x"; done < input.txt`.
</b></details>

<details>
<summary>Как сравнить длины значений переменных?</summary><br><b>

```bash
left=${1-}
right=${2-}
if (( ${#left} != ${#right} )); then
    printf '%s\n' 'Длины различаются'
fi
```

Длина зависит от locale: при UTF-8 это число символов, не байтов и не визуальных графем.
</b></details>

<a id="shell-scripting---conditionals"></a>
#### Сценарии оболочки — условия

<details>
<summary>Объясните условные конструкции и покажите их применение.</summary><br><b>

`if` проверяет статус команды, а не специальный булев тип: ноль — успех. Например: `if test -f "$path"; then printf '%s' 'exists'; else printf '%s' 'missing'; fi`. Bash также поддерживает `[[ ... ]]` с дополнительными правилами; он не является POSIX sh.
</b></details>

<details>
<summary>Как записать отрицание условия в сценарии оболочки?</summary><br><b>

Префикс `!`: `if ! grep -q -- "$pattern" "$file"; then ...; fi`. Учтите, что grep возвращает 1 при отсутствии совпадений и больший код при ошибке: простое отрицание объединяет оба случая, поэтому при необходимости различайте статусы.
</b></details>

<details>
<summary>Как проверить, является ли переданный аргумент числом?</summary><br><b>

Сначала определите формат. Для целого десятичного числа: `[[ ${1-} =~ ^[+-]?[0-9]+$ ]]`. Это проверка записи, а не диапазона. Перед арифметикой ограничьте число цифр, отдельно обработайте знак и основание: `08` нельзя напрямую считать десятичным в арифметике Bash. Исполняемый пример в [решении суммы](solutions/sum.md). Дроби, экспоненциальная запись и разделители требуют другого контракта; удаление части строки до точки не является проверкой числа.
</b></details>

<a id="shell-scripting---arithmetic-operations"></a>
#### Сценарии оболочки — арифметические операции

<details>
<summary>Как выполнять арифметические операции с числами?</summary><br><b>

В Bash целочисленно: `result=$((a + b))`, проверка `((a > b))`. Десятичная арифметика требует другого инструмента, например awk/bc. Для недоверенных строк сначала проверяйте формат и допустимый диапазон: арифметическое расширение не является безопасным валидатором произвольного ввода.
</b></details>


<details>
<summary>Как проверить, делится ли число на 4 без остатка?</summary><br><b>

Для уже проверенного и нормализованного целого `number`: `if (( number % 4 == 0 )); then printf '%s\n' 'Делится'; fi`. Внешний ввод сначала проверяется, например как в [решении суммы](solutions/sum.md).
</b></details>

<a id="shell-scripting---loops"></a>
#### Сценарии оболочки — циклы

<details>
<summary>Что такое цикл? Какие виды циклов вам известны?</summary><br><b>

Повторение команд: `for` перебирает элементы, `while` повторяет при успешном условии, `until` — пока условие не станет успешным. В Bash есть арифметический for. Нужны условие завершения, обработка ошибок и ограничения для повторов внешних запросов.
</b></details>

<details>
<summary>Покажите применение циклов.</summary><br><b>

`for file in ./*.log; do [ -e "$file" ] || continue; printf '%s\n' "$file"; done` — пример обхода файлов с сохранением пробелов. Для чтения строк: `while IFS= read -r line || [ -n "$line" ]; do printf '%s\n' "$line"; done < input.txt`. Для имён с переводами строк используйте NUL-разделители, а не чтение построчно.
</b></details>

<a id="shell-scripting---substring"></a>
#### Сценарии оболочки — подстроки

<details>
<summary>Как получить часть строки после последней точки?</summary><br><b>

`${var##*.}` удаляет самый длинный префикс, заканчивающийся точкой: из `a.b.c` получится `c`. Без точки возвращается исходная строка, при завершающей точке — пустая. `${var//*.}` означает замену всех совпадений шаблона и здесь вводит в заблуждение.
</b></details>

<details>
<summary>Как получить часть строки до последней точки?</summary><br><b>

`${var%.*}`
</b></details>

<a id="shell-scripting---misc"></a>
#### Сценарии оболочки — разное

<details>
<summary>Сгенерируйте случайное восьмизначное число.</summary><br><b>

`shuf -i 10000000-99999999 -n 1` (GNU coreutils). Границы включены. Не используйте этот пример для паролей и криптографических секретов.
</b></details>

<details>
<summary>Приведите примеры хороших практик написания сценариев Bash.</summary><br><b>

Явно задайте поддерживаемую оболочку, заключайте расширения в кавычки, используйте `--` где поддерживается, проверяйте статусы и входные данные. Не разбирайте ls и не используйте eval для пользовательского ввода. Для временных файлов — mktemp и cleanup через trap. `set -e`/pipefail полезны при понимании их исключений; они не заменяют обработку ошибок. Проверяйте bash -n, ShellCheck и поведение на граничных входах.
</b></details>

<details>
<summary>Что такое тернарный оператор? Как его использовать в Bash?</summary><br><b>

Это краткая форма выбора между двумя значениями по условию. В исходнике приведена похожая по назначению цепочка команд:

`[[ $a = 1 ]] && b="yes, equal" || b="nope"`

Она не является собственно тернарным оператором: команда после `||` выполнится и при ошибке команды после `&&`. Арифметический тернарный оператор Bash имеет форму `условие ? значение1 : значение2` внутри арифметического выражения.
</b></details>

<details>
<summary>Что делает следующий код и когда его стоит использовать?

<code>diff <(ls /tmp) <(ls /var/tmp)</code>

</summary><br>
Это подстановка процесса (process substitution). В данном примере сравнивается текстовый вывод ls: содержимое файлов и полное равенство каталогов так не проверяются. Для этого задания используйте [рекурсивное сравнение](solutions/directories_comparison.md). Она позволяет передать вывод команды другой команде в ситуациях, когда конвейер <code>|</code> не подходит. Например, если программа не читает <code>STDIN</code> либо ей нужно передать результаты нескольких команд.
https://superuser.com/a/1060002/167769
</details>

<details>
<summary>Чем вы тестируете сценарии оболочки?</summary><br><b>

`bash -n` проверяет синтаксис, ShellCheck — типичные статические ошибки, Bats или subprocess-тесты — поведение. Проверяйте статусы, stdout/stderr, пустые аргументы, пробелы/переводы строк в именах, отсутствие зависимостей и ошибки команд. В этом репозитории [Bash-тесты](../../tests/shell_unittest.py) запускают реальные `.sh` в временных каталогах; ping заменён заглушкой.
</b></details>

<details>
<summary>Что гарантируют set -e, set -u и pipefail?</summary><br><b>

`-e` завершает оболочку при некоторых неуспешных командах, но имеет исключения, например условия if/while и части AND/OR-списков. `-u` сообщает об обращении к неустановленным параметрам; опциональные значения задавайте через `${var-}`. `pipefail` делает статусом конвейера статус самой правой неуспешной команды, иначе — последней команды. Это полезные настройки, но ошибки с ожидаемыми кодами (diff, grep, ping) нужно обрабатывать явно.
</b></details>

<details>
<summary>Почему изменение переменной внутри конвейера может потеряться?</summary><br><b>

В обычном Bash компоненты конвейера выполняются в subshell. Поэтому `printf '%s\n' one | while read -r x; do count=1; done` обычно не меняет count в родительской оболочке. Используйте перенаправление `while IFS= read -r x; do ...; done < file` или process substitution `< <(command)`; статус асинхронного источника при этом требует отдельного контроля. Настройка lastpipe меняет часть поведения и не должна предполагаться по умолчанию.
</b></details>

<details>
<summary>Как передать произвольные имена файлов между командами?</summary><br><b>

Используйте NUL-разделители, например `find . -type f -print0` и `while IFS= read -r -d '' path; do ...; done`. Имя файла может содержать пробел, табуляцию и перевод строки, но не NUL. Не сохраняйте такой поток в переменной через command substitution: строки Bash не хранят NUL. При вызове команд заключайте путь в кавычки и используйте `--`, если команда его поддерживает.
</b></details>

<details>
<summary>Как убрать временный каталог при завершении сценария?</summary><br><b>

```bash
tmpdir=$(mktemp -d) || exit 1
trap 'rm -rf -- "$tmpdir"' EXIT
trap 'exit 130' INT
trap 'exit 143' TERM
```

Каталог создан самим сценарием; путь нельзя подменять внешним вводом. EXIT trap срабатывает при обычном выходе и явном exit. SIGKILL и аварийное отключение питания обработать таким способом нельзя. Не переопределяйте tmpdir после установки trap.
</b></details>

Официальные справочники: [Bash](https://www.gnu.org/software/bash/manual/bash.html), [GNU find: удаление](https://www.gnu.org/software/findutils/manual/html_node/find_html/Delete-Files.html), [GNU diff](https://www.gnu.org/software/diffutils/manual/diffutils.html), [GNU du](https://www.gnu.org/software/coreutils/manual/html_node/du-invocation.html).
