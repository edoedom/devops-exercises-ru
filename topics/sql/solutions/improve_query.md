## Границы диапазона дат

```sql
SELECT COUNT(*) AS purchases_in_2017
FROM shawarma_purchases
WHERE purchased_at >= '2017-01-01'
  AND purchased_at < '2018-01-01';
```

Полуинтервал включает весь последний день года при хранении времени и не требует угадывать последнюю долю секунды. Запись `2017-31-12` из исходного ответа неверна для ISO YYYY-MM-DD. Для DATE включительная граница `2017-12-31` допустима; для timestamp она обычно означает полночь и пропускает оставшуюся часть дня.

`BETWEEN` сам по себе не мешает индексу: он включает обе границы. Проблемой здесь были границы диапазона, а не обязательная «медленность BETWEEN». Применение функции к индексированному столбцу может потребовать expression index или другого плана; выбор зависит от СУБД, данных и статистики. Проверяйте EXPLAIN на своей нагрузке.

COUNT(*) считает строки. COUNT(purchased_at) не считает NULL, но в этой выборке WHERE уже исключает NULL, поэтому результаты совпадают. В приложении передавайте границы параметрами драйвера. Для timestamp с часовой зоной сначала определите, календарный год какой зоны требуется, и используйте соответствующие абсолютные границы.

[Запрос для регрессионного теста](../examples/date_range/query.sql) проверяется на датах до/в начале года, в конце 31 декабря, в начале следующего года и NULL. SQLite-тест использует канонические ISO-строки, а не доказывает поведение всех типов timestamp во всех СУБД.
