# Elasticsearch, Kibana и AWS

Разверните кластер Elasticsearch и панель Kibana в одном из облаков:

* AWS.
* OpenStack.
* Azure.
* GCP.

Подробно опишите план развёртывания, желательно со схемами. Объясните:

* Как увеличивать и уменьшать масштаб системы.
* Как разворачивать кластер менее чем за 20 минут.
* Как применять политику безопасности для управления доступом.
* Как передавать журналы приложения в ELK.
* Как работать с несколькими приложениями в разных регионах.

<a id="solution"></a>
# Решение

Это один из возможных вариантов, в основном использующий AWS.

* Создайте VPC с подсетью, чтобы узлы Elasticsearch находились только во внутренней сети. При необходимости настройте NAT для исходящего доступа к публичной сети.
* Создайте роль IAM для доступа к кластеру и отдельную роль администратора.
* Для быстрого развёртывания рабочей среды используйте управляемый сервис Elasticsearch от AWS. Это также позволяет охватить несколько зон доступности. Для аутентификации в исходном варианте предлагается Amazon Cognito или корпоративный LDAP-сервер.
* Для передачи данных установите Logstash на экземплярах. Он будет отправлять данные в Elasticsearch.
* Для мониторинга используйте CloudWatch для наблюдения за потреблением ресурсов кластера и панель облачных метрик.
* Для работы с данными из разных регионов в исходном варианте предлагается передавать их в S3 и объединять на одной панели.

> Примечание к переводу: это общий эскиз из оригинала, а не готовая конфигурация. Подключение LDAP и построение общей панели по данным S3 требуют отдельной проработки.
